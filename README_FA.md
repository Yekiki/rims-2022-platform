# سامانه پژوهشی RIMS 2022 — نسخه MySQL

این نسخه برای اجرای برنامه با **MySQL 8.0 یا جدیدتر** بازنویسی شده است. ورود با لینک ایمیل حذف شده؛ مدیر سامانه با نام کاربری و رمز عبور وارد می‌شود و پاسخ‌دهنده پس از ورود به صفحه شروع، نشست امن و بدون ایمیل دریافت می‌کند.

## ۱. پیش‌نیازها

- Node.js نسخه 20 یا جدیدتر
- MySQL نسخه 8.0 یا جدیدتر
- یک پایگاه داده و کاربر MySQL با مجوزهای لازم برای ساخت/تغییر جدول‌ها

## ۲. نصب وابستگی‌ها

در پوشه پروژه اجرا کنید:

```bash
npm install
```

## ۳. ساخت پایگاه داده

یک پایگاه داده خالی با کدگذاری `utf8mb4` بسازید. سپس فایل `mysql/schema.sql` را فقط یک بار روی همان پایگاه داده اجرا کنید. برای نمونه از خط فرمان:

```bash
mysql -u root -p rims_research < mysql/schema.sql
```

اگر نام پایگاه داده شما `rims_research` نیست، نام خودتان را جایگزین کنید. اگر از MySQL Workbench استفاده می‌کنید، محتوای `mysql/schema.sql` را در یک Query باز کرده و اجرا کنید.

## ۴. تنظیم متغیرهای محیطی

فایل `.env.example` را به `.env.local` کپی کنید و مقادیر واقعی را وارد کنید:

```env
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=rims_app
MYSQL_PASSWORD=رمز_قوی_کاربر_دیتابیس
MYSQL_DATABASE=rims_research
MYSQL_SSL=false
SESSION_SECRET=یک_رشته_تصادفی_حداقل_۳۲_نویسه‌ای
ADMIN_USERNAME=researcher
ADMIN_PASSWORD=یک_رمز_منحصربه‌فرد_حداقل_۱۲_نویسه‌ای
ADMIN_FULL_NAME=پژوهشگر
```

`SESSION_SECRET` باید حداقل ۳۲ نویسه تصادفی داشته باشد. رمز مدیر را در فایل یا پیام عمومی منتشر نکنید.

## ۵. انتقال اطلاعات موجود از Supabase

اگر می‌خواهید اطلاعات فعلی را نگه دارید، **قبل از اجرای seed**، ابتدا روی یک پایگاه داده MySQL خالی فایل `mysql/schema.sql` را اجرا کنید. سپس به‌طور موقت این متغیرها را در `.env.local` تنظیم کنید:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_OLD_SERVICE_ROLE_KEY
```

برای تخصیص نام کاربری و رمز عبور به مدیر موجود، `ADMIN_USERNAME` و `ADMIN_PASSWORD` را نیز تنظیم کنید. اگر بیش از یک پروفایل مدیر در Supabase وجود دارد، مقدار `ADMIN_USER_ID` را برابر شناسه پروفایل مدیریتی موردنظر قرار دهید.

سپس اجرا کنید:

```bash
npm run migrate-supabase
```

اسکریپت فقط پایگاه داده MySQL خالی را می‌پذیرد و اطلاعات سازمان‌ها، کاربران، دعوت‌ها، پرسش‌ها، پاسخ‌ها، ارزیابی‌ها، نتایج و گزارش‌های ممیزی را منتقل می‌کند. این اسکریپت داده‌های موجود را بازنویسی نمی‌کند.

پس از پایان انتقال:

1. تعداد رکوردها و چند ارزیابی نمونه را در MySQL بررسی کنید.
2. کلید `SUPABASE_SERVICE_ROLE_KEY` قدیمی را در داشبورد Supabase تعویض کنید.
3. متغیرهای مربوط به مهاجرت را از محیط اجرای عادی حذف کنید.
4. در دوره انتقال، اگر می‌خواهید کاربران فعلی با همان مرورگر نشست قدیمی خود را یک‌بار به کوکی جدید تبدیل کنند، متغیرهای `LEGACY_SUPABASE_*` و `NEXT_PUBLIC_LEGACY_SUPABASE_*` را موقتاً نگه دارید. پس از انتقال نشست کاربران، این متغیرها و مسیر `/api/session/legacy` را حذف کنید.

**مهم:** توکن نشست قدیمی فقط برای تأیید و تبدیل یک نشست موجود استفاده می‌شود؛ کد ورود ایمیلی جدیدی ارسال نمی‌شود. اگر نشست قدیمی کاربر منقضی شده باشد یا مرورگر قبلی در دسترس نباشد، ممکن است لازم شود دسترسی آن کاربر را مدیر سامانه بازیابی کند.

## ۶. آماده‌سازی داده‌ها و حساب مدیر

اگر پایگاه داده تازه است و داده‌ای از Supabase منتقل نمی‌کنید، ابتدا کاتالوگ پرسش‌نامه را بسازید:

```bash
npm run seed
npm run grant-admin
```

اگر داده‌ها را از Supabase منتقل کرده‌اید، `npm run seed` را اجرا نکنید؛ کاتالوگ در مهاجرت منتقل شده است. در این حالت اگر رمز مدیر را هنگام مهاجرت تنظیم نکرده‌اید، فقط این دستور را اجرا کنید:

```bash
npm run grant-admin
```

این دستور از `ADMIN_USERNAME` و `ADMIN_PASSWORD` در `.env.local` استفاده می‌کند و رمز را به‌صورت هش‌شده ذخیره می‌کند.

## ۷. اجرا و بررسی

```bash
npm run dev
```

سپس برای بررسی اتصال و داده‌های اصلی اجرا کنید:

```bash
npm run smoke
npm run typecheck
npm test
npm run build
```

## ۸. روش ورود

- **پاسخ‌دهنده:** از «شروع ارزیابی» وارد می‌شود؛ ایمیل لازم نیست. نشست در کوکی `HttpOnly` نگهداری می‌شود و برای ادامه ارزیابی ناتمام باید از همان مرورگر استفاده کند.
- **پژوهشگر/مدیر:** از «ورود پژوهشگر» با نام کاربری و رمز عبور وارد می‌شود. هیچ لینک ورود ایمیلی ارسال نمی‌شود.
- **کد دعوت:** همچنان از پنل مدیر ساخته می‌شود و فقط یک‌بار قابل استفاده است.

## نکات امنیتی

- فایل `.env.local` را به دیگران ارسال یا وارد Git نکنید.
- از کاربر اختصاصی MySQL با حداقل مجوز لازم استفاده کنید؛ برای اجرای عمومی از حساب `root` استفاده نکنید.
- سایت را فقط روی HTTPS منتشر کنید تا کوکی امن نشست در محیط تولید فعال باشد.
- پس از اتمام انتقال نشست‌های قدیمی، کلیدها و مسیر موقت انتقال از Supabase را حذف کنید.
- پیش از استفاده پژوهشی واقعی، ورود مدیر، کد دعوت، ثبت پاسخ، ثبت نهایی، سطح بلوغ و خروجی Excel را با داده آزمایشی بررسی کنید.
